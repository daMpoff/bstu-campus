# Аудит трёх переходов

Проверка в Edge на изолированном демо. Начальная точка после входа: профиль студента, задания преподавателя или администрирование. Для гостя начальная точка — главная.

Считаем переходы между страницами, вкладками или панелями до видимого целевого элемента. Ввод данных, выбор записи в форме и подтверждение операции учитываются отдельно. Для действия, требующего существующего объекта, использовали подготовленное демо-задание, активность или опрос.

## Гость и студент

- Вход с главной — 1. Форма регистрации с главной — 2.
- История баллов — 0. Сдача ближайшей работы через дашборд — 1, через общий список заданий — 2.
- Ближайший опрос из дашборда — 1, произвольный опрос из списка — 2.
- Ближайшая активность из дашборда — 1. Ссылка приводит к карточке, где доступна запись, если активность общественная и запись открыта.
- Активности, личные события, лента наград и справочный помощник — по 1.
- Рейтинг с пьедесталом и фильтрами — 1. Настройки профиля с кодом Telegram — 1. Отправка кода выполняется в Telegram.

## Преподаватель

- Создание задания — 1. Очередь проверки — 1. Предпросмотр из очереди — 2. Пакетная проверка открывается из карточки задания за 1.
- Создание активности и подтверждение участия — по 2. Создание опроса и просмотр статистики опроса — по 2.
- Подтверждение группы, рейтинг, аналитика, личные события и лента наград — по 1. Профиль студента из рейтинга — 2.
- Помощник — 1. Начало личного назначения в помощнике — 2.

## Администратор

- Справочники — 0. Форма добавления записи, импорт CSV и настройки — по 1. Лента наград — 1.
- Ссылки из ответов помощника открывают нужную вкладку импорта или настроек напрямую.

## Многошаговые действия

- В помощнике поиск и выбор получателя, выбор задания и подтверждение выполняются в одной панели. Эти действия нужны для проверки адресата и содержимого перед отправкой.
- Для нового пользователя подтверждение email выполняется по ссылке из письма. Группу затем подтверждает преподаватель в своём кабинете. Это отдельные действия двух ролей.
- Браузерная проверка маршрутов описана в `frontend/e2e/navigation.spec.ts`. Подтверждение отправки, видимость личного задания и доступ к вложению проверяет `frontend/e2e/assistant.spec.ts`.
