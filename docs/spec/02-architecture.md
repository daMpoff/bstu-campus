# Архитектура

- React + TypeScript + Vite. Интерфейс вызывает REST API на том же origin. Vite проксирует API при локальной разработке.
- Spring Boot 4.1 и Java 21. Spring Security проверяет роли, защищает операции от CSRF и хранит идентификатор сессии в HttpOnly cookie.
- PostgreSQL 17, Flyway для миграций и Spring JdbcClient для доступа к данным. Явные SQL-запросы задают порядок блокировок при изменении работ и рейтинга. Храним пользователей, справочники, задания, целевые группы, состояния работ и журнал АР.
- Регистрация проверяет справочники PostgreSQL и сохраняет пароль как хеш BCrypt. Подтверждение адреса использует одноразовый токен с ограниченным сроком. В базе подтверждения хранится хеш токена. Подтверждение группы и создание задания блокируют одну запись группы, чтобы студент получил все её открытые задания независимо от порядка операций.
- Файл работы выдаётся только после проверки доступа. Дедлайн вводится по московскому времени, на API передаётся как UTC.
- Планировщик проверяет активные просроченные работы. Транзакция блокирует работу и студента, учитывает наступившие интервалы и записывает списание вместе с балансом. Перед сдачей тот же расчёт закрывает ещё не обработанные интервалы. При нулевом балансе фоновая проверка двигает время без записи о списании. После возврата отсчёт возобновляется с нового интервала.
- API профиля читает балансы, историю и списки заданий в одной транзакции с повторяемым чтением. Профиль доступен авторизованным пользователям. В чужом профиле задания показаны без ссылок на сдачу и вложения. Права на просмотр работы и скачивание файла проверяются отдельно.
- Семестровый планировщик фиксирует обработанный семестр, пополняет балансы и записывает фактические прибавки в журнал в одной транзакции. Уникальность семестра защищает от повторов при запуске нескольких экземпляров и при изменении даты. Для старых аккаунтов пополнение доступно с даты миграции, а для новых со следующего дня после регистрации.
- Обзор преподавателя читает задания, счётчики и очередь в одном снимке базы. Прогресс считается по назначенным работам. Рейтинг группы читается из текущих балансов студентов через API, доступный преподавателям.
- Запись на общественную активность доступна студентам целевых групп до начала. При подтверждении система проверяет эту запись. БУА и БОА расходуют общий бюджет преподавателя по группе и месяцу. Начисление и расход сохраняются в одной транзакции. Уникальная запись на пару «активность — студент» защищает от повтора, а условное обновление строки бюджета защищает от превышения лимита при одновременных начислениях.
- Профиль читает отдельные балансы БУА и БОА из начислений и объединяет их с операциями АР в личной истории. Общая лента читает те же начисления и загружает старые записи по курсору из времени и идентификатора начисления.
- Опрос связывает вопросы, варианты и группы. Голос сохраняется одной транзакцией с уникальностью по студенту и опросу. Для анонимных опросов API выдаёт агрегаты без имён и индивидуальных ответов.
- Триггеры PostgreSQL записывают события кабинета в той же транзакции, что и действие. Планировщик добавляет однократные напоминания о дедлайнах и завершениях опросов. Лента фильтрует записи по получателю. Очередь SMTP использует уникальный идентификатор события, задержку повторной отправки и срок для напоминаний. История, перенесённая при миграции, не отправляется повторно по почте.
- Настройки из кабинета администратора хранятся в `campus_settings`, при отсутствии строки применяются параметры запуска. Справочники и CSV-импорт проверяются на сервере. Аналитика строится по журналу АР, активности и расходу бюджета за выбранные месяцы.
- Генератор черновика вызывает настроенный Chat Completions API из бэкенда. Ключ остаётся на сервере, в запрос попадают введённые тезисы. Сгенерированный черновик проходит проверку формы перед публикацией.
- Для свободного вопроса студента Chat Completions получает справку и описание инструмента чтения сводки. Сервер проверяет имя функции и период из ответа модели. Браузер запрашивает сводку через MCP Streamable HTTP. Spring Security проверяет сессию, роль и CSRF. Сервер проверяет Origin и вычисляет данные по имени из сессии. Задания, текущий АР и журнал читаются в одной транзакции с повторяемым чтением. Сводка выводится в браузере без передачи данных кабинета модели.
- Docker Compose запускает приложение, базу и локальный SMTP-приёмник. Образ приложения собирает фронтенд и включает его в Spring Boot.
